# Codex ACP live verification: 2026-08-12

Issue: #25. All timestamps are UTC. Responses and diagnostics below are
sanitized; no credentials or credential files were read.

## Environment

- Standalone CLI: `codex-cli 0.147.0`
- Sign-in check: `codex login status` reported `Logged in using ChatGPT`
- Adapter on `PATH`: deprecated `@zed-industries/codex-acp 0.16.0`
- Adapter embedded Codex runtime: `rust-v0.137.0`
- ACP SDK: `@agentclientprotocol/sdk 1.2.1`
- Maintained adapter available from npm:
  `@agentclientprotocol/codex-acp 1.1.14`

## Reproducible baseline

At `2026-08-11T18:04:48Z`, `npm run smoke:acp -- codex` opened a real ACP
session but failed its prompt. The signed-in service selected `gpt-5.6-sol`;
the legacy adapter reported that the model required a newer Codex version. It
also failed to decode the newer `max` reasoning-effort model metadata. Vellum
received a terminal ACP error rather than useful streamed text.

The baseline also exposed an orphan native `codex-acp` process after the npm
launcher exited. Regression tests now require `dispose()` and handshake
failure to wait for adapter exit. POSIX cleanup terminates the complete adapter
process group.

## Signed-in live proof

The stable standalone CLI completed the exact-response prompt with `gpt-5.5`,
proving that model is available through the existing ChatGPT sign-in. Vellum
then ran its real first-party ACP path twice with
`VELLUM_CODEX_MODEL=gpt-5.5`.

Both Vellum sessions:

- completed `StdioAcpClient.newSession("codex")`;
- streamed the useful text `pong`;
- emitted update kinds including `text`, `tool_result`, and `done`;
- terminated with `stopReason: end_turn`;
- used no raw API key, custom gateway, or third-party OAuth bridge.

Final post-fix runs:

| Run | Start | End | Terminal result | Orphan query |
| --- | --- | --- | --- | --- |
| 1 | `2026-08-12T01:32:35.106Z` | `2026-08-12T01:32:47.333Z` | `done/end_turn` | empty |
| 2 | `2026-08-12T01:32:58.702Z` | `2026-08-12T01:33:09.523Z` | `done/end_turn` | empty |

The legacy adapter continued to log its model-metadata decode error on stderr,
but the explicit supported-model override allowed both turns to complete. The
maintained adapter should replace the deprecated package as a local
prerequisite; executable-name compatibility alone is not enough evidence.

## Cleanup evidence

Before the lifecycle fix, native adapter processes survived under PID 1. After
the fix, disposal targets the POSIX process group and waits for it to disappear,
with bounded `SIGKILL` escalation. Final verification reran the smoke twice
and recorded an empty `codex-acp` / `codex app-server` process query after each
session.

Exact post-session process check:

```bash
ps -axo pid,ppid,state,lstart,command | rg '[c]odex-acp|[c]odex app-server'
```

It produced no matching rows after either final run.
